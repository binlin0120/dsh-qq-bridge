# 2026-10-30 维护更新

此维护版基于上游 v0.2.0-r4；保留原作者版权与 MIT 许可。提交更新不代表重新发布或打包 SnowLuma、DSH 或个人配置。

## 使用体验

- 群友在已授权群中明确请求新图片时，每个真实 QQ 号每天可生成 1 张，不同群共用，北京时间零点刷新，重启保留用量。主人不占群友次数，访客私聊照片默认每天 3 张，二者不受关闭通用用量限制影响。
- 修复 Windows 参考图缓存目录的大小写/路径别名校验，并统一人格卡换行解析；相邻目录、其他磁盘和目录逃逸仍被拒绝。
- 临时内部订阅关闭后，主会话仍能订阅新会话，避免连接存活却收不到结果。换对话先交接并校验作用域记忆，成功后才替换映射；群聊与访客不继承私人记忆。
- 好友申请先保存并独立通知主人，依据主人当前明确指令审批，回读实际好友列表后才确认；多目标或含糊审批不猜测。
- “先不弄了”等自然停令撤销后续投递；后台结果先转换成当前会话的自然回复，不直接发送内部处理报告。
- 增加有来源的本地分层记忆和历史召回，不下载向量模型，不启用外部向量服务；课表旧记录不会自动重建提醒。
- 收藏表情的默认自主程度为 0.7，表示按语境自然选用的倾向，不是每条消息固定发送概率。

## 维护与部署

- 主入口缩减为启动器，业务拆为 31 个功能模块；增加统一测试登记与 Windows/Linux、Node 22/24 CI 配置。CI 显式安装 Python 与固定版本 Pillow，以运行真实参考图处理夹具。
- 未处理异常保存最小状态后非零退出，配合 systemd 等进程管理器恢复；模型与传输调用有截止时间，取消后的晚到结果不继续投递。
- 空名单保持拒绝，`allowAllWhenEmpty: true` 不再被接受。依赖锁定版本；SnowLuma ESM 修补按版本和逐文件哈希核验，未知内容在修改前拒绝。
- Windows `.bat` 启动器按原始 CRLF 字节入库，克隆或下载源码归档后也可通过启动格式校验。
- 删除指向缺失语音目录的 npm 启动别名；内置发送仍用 `npm run send-voice`，独立图形工具需另行安装。

## 升级注意事项

1. 在独立候选目录使用仓库附带的 `.npmrc` 执行 `npm ci`、`npm run compat:verify` 和 `npm test`，验证后再切换部署。不要直接用开源模板覆盖正在运行的私有目录。
2. 保留私有 `config.json`、完整 `state/`、配置的工作目录和私人素材；尤其保留记忆、提醒、群媒体授权、请求回执与会话交接数据。项目不随源码分发这些内容。
3. 检查 `ownerQQ` 和允许名单；旧配置若为 `allowAllWhenEmpty: true`，需先改为 `false` 并补齐允许名单，否则新版本拒绝启动。
4. 群友生图默认开放每天 1 张，需要自行配置兼容异步任务协议的图片服务、密钥环境变量及角色参考图；不希望开放时设置 `groupPhotos.enabled: false`。此入口沿用角色照片链路，不代表任意通用图片 API。
5. 图片入队即占当天次数，失败或结果不确定不自动退还或重新付费；重复消息复用原任务。新的好友申请会尝试独立通知主人，未知通知结果不盲目重发。
6. 进程故障恢复依赖部署方配置的重启策略。默认离线测试不发送 QQ 消息，不调用付费图片生成；DSH、真实 QQ 收图和可选媒体工具需按实际环境另行验收。
